# AI Senior Project Manager + CFO + Daily Operating System

## Overview

The TFR Construction Management Platform now features a comprehensive AI-powered system that acts as a Senior Project Manager and CFO, providing daily operational insights, task generation, profitability analysis, crew scheduling, material ordering automation, bid tracking, and billing intelligence.

Powered by OpenAI's GPT-4, this system analyzes all project data across 19 database tables and generates actionable, role-specific recommendations to make TFR's operations more proactive, profitable, and efficient.

## Architecture

### Backend Components

#### 1. Database Schema (`shared/schema.ts`)

**ai_settings Table:**
- Stores system-wide AI configuration
- Controls daily run schedule (time, enabled/disabled)
- Feature toggles for each AI capability
- Model selection (gpt-4o, gpt-4-turbo-preview)
- Single-row table (ID-based singleton)

**ai_runs Table:**
- Tracks every AI analysis execution
- Stores complete snapshots, profitability data, and AI responses
- Supports manual and scheduled runs
- Status tracking (in_progress, completed, failed)
- Indexed on createdAt for efficient querying

**ai_tasks Table:**
- Individual actionable tasks generated by AI
- Role-based assignment (ADMIN, MANAGER, SUPERINTENDENT, ESTIMATOR, OFFICE_MANAGER, HOURLY_EMPLOYEE)
- Priority levels (CRITICAL, HIGH, MEDIUM, LOW)
- Status workflow (PENDING → IN_PROGRESS → COMPLETED/DISMISSED)
- Foreign key to ai_runs for audit trail
- Optional project association
- Indexed on role, status, priority for fast filtering

#### 2. AI System Prompt (`server/ai/systemPrompt.ts`)

Defines the AI's role, responsibilities, and output structure:

**Responsibilities:**
1. Generate role-based daily tasks with specific actions
2. Analyze project profitability (CFO-level)
3. Recommend crew scheduling optimizations
4. Alert on urgent material orders
5. Track bid deadlines and follow-ups
6. Monitor billing cycles and overdue invoices

**Output Schema:**
- Strict JSON structure enforced via OpenAI's `response_format`
- Includes analysis summary, profitability insights, tasks array, crew recommendations, material orders, billing alerts, and bid reminders
- Every task includes: type, role, priority, title, description, due date, project code, metadata

**Guidelines:**
- Use actual data, never hallucinate numbers
- Be specific and actionable (reference project codes, amounts, dates)
- Flag issues proactively before they become crises
- Generate 10-30 tasks daily across all roles
- Balance tactical needs with strategic insights

#### 3. OpenAI Client (`server/ai/openaiClient.ts`)

**Configuration:**
- Uses OpenAI SDK with API key from environment
- Model selection: gpt-4o (default) or gpt-4-turbo-preview
- Enforces JSON output via `response_format: { type: 'json_object' }`
- Temperature: 0.7 (balanced creativity and consistency)
- Max tokens: 4096 (supports comprehensive responses)

**Type Safety:**
- Fully typed AIAnalysisResponse interface
- Validates parsed JSON structure
- Error handling with detailed logging

#### 4. Data Snapshot Builder (`server/ai/snapshotBuilder.ts`)

Aggregates comprehensive operational data from across the platform:

**Data Sources:**
1. **Projects:** Active/planning projects with budgets, timelines, superintendents
2. **Labor:** Weekly time entries, hours, costs, unapproved entries, active shifts
3. **Procurement:** Pending orders, urgent items (needed within 3 days)
4. **Change Orders:** Pending approvals, recent approvals, total value
5. **Billing:** YTD invoices/payments, overdue invoices (30+ days)
6. **Bids:** Active bids, upcoming deadlines, total value
7. **Crew:** Employee counts by role, overtime hours

**Performance:**
- Efficient database queries with limits (50-1000 records per query)
- In-memory aggregation and calculations
- Snapshot completed in <5 seconds typical case

**Data Quality:**
- Defensive number parsing (Number() with fallbacks)
- Date validation and timezone handling
- Null-safe property access

#### 5. Profitability Engine (`server/ai/profitabilityEngine.ts`)

Deterministic financial calculations per project:

**Calculations:**
- **Labor Cost:** Sum of (hours × hourly_rate) for all time entries
- **Material Cost:** Actual cost (or estimated if actual unavailable) from procurement
- **Other Expenses:** Total from receipts table
- **Approved Change Orders:** Sum of approved CO values
- **Adjusted Budget:** Base budget + approved COs
- **Variance:** Adjusted budget - actual costs
- **Variance %:** (variance / adjusted budget) × 100

**Status Determination:**
- **ON_BUDGET:** Variance ≥ 10%
- **MINOR_CONCERN:** 0% ≤ Variance < 10%
- **MAJOR_RISK:** Variance < 0% (over budget)

**Projected Completion Cost:**
- Simple heuristic: (actual cost / percent_complete) × 100
- Percent complete based on timeline (start date → estimated completion)

**Key Metrics:**
- Labor efficiency (actual hours vs budgeted hours)
- Material spend rate (actual spend vs budget allocation)
- Pending change order value

**Export:**
- `calculateProjectProfitability(code)`: Single project
- `calculateAllProjectsProfitability()`: All active projects, sorted by risk

#### 6. AI Orchestrator (`server/ai/orchestrator.ts`)

Coordinates the entire AI analysis workflow:

**runAIAnalysis() Flow:**
1. Generate unique run ID
2. Create ai_runs record with status='in_progress'
3. Build data snapshot (all operational data)
4. Calculate profitability for all active projects
5. Fetch AI settings (feature toggles, model)
6. Construct user prompt with snapshot + profitability
7. Call OpenAI with system prompt + user prompt
8. Parse and validate JSON response
9. Update ai_runs with results (status='completed')
10. Create ai_tasks from response
11. Log success/failure

**Helper Functions:**
- `getLatestAIRun()`: Most recent completed run
- `getAIRunById(id)`: Specific run by ID
- `getTasksForRun(runId)`: All tasks from a run
- `getTasksForRole(role, status?)`: Role-filtered tasks
- `updateTaskStatus(taskId, status, userId?)`: Task state transitions

**Error Handling:**
- Try-catch wrapping entire run
- Errors logged to ai_runs.errorMessage
- Run status set to 'failed' on exception
- Detailed console logging for debugging

#### 7. Daily Scheduler (`server/ai/scheduler.ts`)

Automated daily execution using node-cron:

**Initialization:**
- Called on server startup (`server/index.ts`)
- Fetches or creates default ai_settings
- Parses dailyRunTime (HH:MM format)
- Constructs cron expression (e.g., "0 6 * * *" for 6:00 AM)
- Schedules task in America/New_York timezone

**Features:**
- Respects dailyRunsEnabled flag
- Validates time format (hour 0-23, minute 0-59)
- Stops and restarts on settings update
- Comprehensive logging (scheduled, running, completed, failed)

**Rescheduling:**
- `rescheduleAIRuns()`: Stop current task, reinitialize with new settings
- Called after AI settings update

#### 8. API Routes (`server/aiRoutes.ts`)

RESTful endpoints with RBAC and rate limiting:

**Settings Management:**
- `GET /api/ai-settings`: Fetch current settings (ADMIN only)
- `PATCH /api/ai-settings`: Update settings (ADMIN only, sensitive rate limiter)

**AI Runs:**
- `POST /api/ai-pm/run`: Trigger manual analysis (ADMIN/MANAGER, sensitive rate limiter)
- `GET /api/ai-pm/latest-run`: Get most recent completed run
- `GET /api/ai-pm/runs/:runId`: Get specific run by ID
- `GET /api/ai-pm/runs`: List all runs (ADMIN/MANAGER, paginated)

**Tasks:**
- `GET /api/ai-pm/tasks`: List tasks for current user's role (with optional status filter)
- `GET /api/ai-pm/tasks/role/:role`: List tasks for specific role
- `PATCH /api/ai-pm/tasks/:taskId`: Update task status (any authenticated user)

**Profitability:**
- `GET /api/cfo/profitability`: Get profitability data from latest run (ADMIN/MANAGER)

**Security:**
- All routes require authentication (`req.user`)
- RBAC checks for ADMIN/MANAGER-only endpoints
- Rate limiting on sensitive operations
- Audit logging for CREATE/UPDATE actions
- JSON parsing with error handling

### Data Flow

#### Daily Scheduled Run

```
06:00 AM (configurable) →
node-cron triggers scheduler →
runAIAnalysis(triggeredById=null) →
Create ai_runs record (status='in_progress') →
buildDataSnapshot() [queries 19 tables] →
calculateAllProjectsProfitability() [per-project analysis] →
Fetch ai_settings [feature toggles] →
Construct user prompt [snapshot + profitability + date + enabled features] →
Call OpenAI GPT-4 with system + user prompts →
Parse JSON response →
Validate structure →
Update ai_runs (status='completed', store all data) →
Create ai_tasks (bulk insert from response.tasks) →
Log success
```

#### Manual Trigger

```
User clicks "Run Analysis Now" (ADMIN/MANAGER) →
POST /api/ai-pm/run →
RBAC check →
runAIAnalysis(triggeredById=userId) →
[Same flow as scheduled run] →
Return runId to frontend →
Frontend invalidates queries →
Dashboard reloads with new tasks
```

#### Task Management

```
User clicks "Start" on pending task →
PATCH /api/ai-pm/tasks/:taskId {status: "IN_PROGRESS"} →
updateTaskStatus(taskId, "IN_PROGRESS", userId) →
Update ai_tasks record (status, assignedToId) →
Audit log (UPDATE action) →
Return updated task →
Frontend invalidates cache →
Task moves to in-progress column
```

#### Profitability View

```
CFO Dashboard loads →
GET /api/cfo/profitability →
RBAC check (ADMIN/MANAGER) →
getLatestAIRun() →
Parse profitabilityData JSON →
Return array of ProjectProfitability →
Frontend displays overview + project cards
```

## Security & Compliance

### API Key Management
- OpenAI API key stored in Replit Secrets
- Server-side only (never exposed to frontend)
- Placeholder key with warning if missing

### Role-Based Access Control
- All routes require authentication
- ADMIN-only: AI settings, run history, all role tasks
- MANAGER: CFO dashboard, profitability data, manual triggers
- All users: Their own role-specific tasks

### Rate Limiting
- Auth endpoints: 10 requests/15 min
- Sensitive endpoints (AI settings, manual run): 100 requests/15 min
- General API: 1000 requests/15 min

### Audit Logging
- All AI setting changes logged
- Manual AI runs logged with triggering user
- Task status updates logged
- Includes IP address, user agent, timestamps

### Data Privacy
- AI snapshots stored in ai_runs for full audit trail
- No PII exposed to OpenAI (only aggregated metrics)
- Task metadata sanitized before storage

## Performance Considerations

### Database Optimization
- Strategic indexes on ai_tasks (role, status, priority)
- Index on ai_runs (createdAt) for efficient latest-run queries
- Query limits to prevent unbounded result sets

### Snapshot Efficiency
- Parallel data fetching where possible
- In-memory aggregation (no temp tables)
- Typical snapshot time: 2-5 seconds

### Profitability Calculations
- Per-project isolation (one failure doesn't block others)
- Cached in ai_runs (recompute only on new run)
- Sorted by risk status for priority display

### Frontend Performance
- TanStack Query caching (1-minute stale time)
- Optimistic UI updates
- Loading skeletons prevent layout shift
- Hierarchical query keys for granular invalidation
