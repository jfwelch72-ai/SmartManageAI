FEATURE A – AI AUTO-TAKEOFF FROM BLUEPRINTS & PHOTOS
=====================================================================

GOAL:
Allow users to upload blueprint PDFs (and optionally photos), run AI computer-vision/LLM analysis, and auto-generate takeoff quantities that feed into existing calculators, SOW items, and the takeoff UI.

1) TECHNICAL SPEC (/docs/feature-A-ai-auto-takeoff.md)
   - Describe:
     - Supported inputs: PDF plans, PNG/JPG images.
     - Use of vision-capable LLM to:
       - Detect drawing scale, title block, legends.
       - Identify areas, linear runs, counts (walls, doors, windows, fixtures, slabs, roofs, etc.).
       - Output normalized JSON with standard units (SF, LF, EA, CY).
     - Integration with:
       - calculators and organization_calculators
       - master_sow_items and organization_sow_items
       - existing takeoff engine data structure.
     - Security (SSRF, file size limits, mime types, org scoping).
   - Clearly define failure modes and fallback (manual takeoff continues to work).

2) API DESIGN
   - New endpoints (examples):
     - POST /api/ai/auto-takeoff/upload
       - Body: { projectId, tradeType, sheetName, fileId or file upload }
       - Behavior: store file, enqueue AI analysis job.
     - GET /api/ai/auto-takeoff/results?projectId=...&sheetId=...
       - Returns AI-generated takeoff JSON: areas, lengths, counts, metadata (confidence, annotations).
   - Reuse existing file-upload patterns (Uppy / object storage).
   - Ensure all requests require authenticated user and organizationId scoping.

3) DATABASE DESIGN
   - New table (through Drizzle migration):
     - auto_takeoff_sheets
       - id (PK)
       - organizationId (FK)
       - projectId (FK)
       - fileUrl / fileKey
       - sheetName
       - status: PENDING / PROCESSING / COMPLETE / FAILED
       - aiResultJson (JSONB)
       - createdAt, updatedAt
   - Optional: auto_takeoff_items (if you want to store each AI-detected measurement as a row).

4) FRONTEND / UI
   - New screen under an existing project:
     - “AI Takeoff” tab for each project.
   - UI flow:
     - Upload plan sheet(s) for AI analysis.
     - Show status per sheet.
     - When COMPLETE, show AI-identified measurements in a table alongside drawing preview.
     - Allow user to:
       - Accept/reject items
       - Map items to SOW/calculator line items
   - Integrate with existing takeoff UI:
     - Option to “Import AI quantities” into calculators/material takeoff.

5) DEVELOPMENT ROADMAP
   - Phase 1: Backend endpoints + DB table + stub AI integration (mock results).
   - Phase 2: Wire frontend UI to results.
   - Phase 3: Replace mocks with real vision API calls.
   - Phase 4: Add trade-specific parsing logic and user feedback loop.

6) INTEGRATION
   - Ensure GC mode vs single-trade mode is respected (different SOW mappings).
   - Use existing master_uom and standard UOMs.
   - Respect RBAC: Only management roles can access AI auto-takeoff.
