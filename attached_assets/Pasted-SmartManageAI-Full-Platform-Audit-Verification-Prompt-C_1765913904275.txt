SmartManageAI Full Platform Audit + Verification Prompt (Copy/Paste)

You are a senior staff full-stack engineer + security engineer. Perform a complete platform audit of this SmartManageAI codebase to verify that every feature, system, integration, relationship, communication, and permission model works correctly after migration to a new owner account.

0) Hard Requirements (DO NOT VIOLATE)

Do NOT remove or weaken any existing features.

Do NOT change existing business logic unless it is clearly broken and you can prove it with a failing test.

Do NOT delete seed data, demo login buttons, or dev/test routes currently required for test users.

Prefer additive changes: add tests, add audit scripts, add logs, add guards, add dashboards.

Every check must be multi-organization aware (org A must never see org B data).

Every check must be reproducible via:

npm run audit (new)

npm run test (existing or enhanced)

a simple “Audit Dashboard” page (new) showing pass/fail.

1) Build an “Audit Harness” (Required)

Create an audit harness that can run locally and in CI.

1.1 Add new commands

Add these scripts to root package.json (or workspace equivalent):

audit: runs ALL audit checks end-to-end

audit:quick: fast subset (smoke + permissions + tenant isolation)

audit:db: schema + migrations + tenant constraints verification

audit:api: route discovery + authz checks + contract validation

audit:ui: UI route smoke checks + RBAC gating verification (headless)

audit:integrations: external integrations mocks + webhook/cron checks

audit:ai: AI isolation + prompt safety + org scoping verification

audit:report: generates a markdown + json report in /audit-reports/

1.2 Output artifacts (Required)

Generate:

/audit-reports/audit-report.json

/audit-reports/audit-report.md

/audit-reports/audit-report.html (optional but preferred)
Include:

timestamp, git commit hash

environment

pass/fail by category

list of failing assertions with exact file + line + reproduction steps

2) Multi-Org + RBAC + Super Admin (Most Critical)
2.1 Tenant isolation verification (server-side)

Create automated tests that prove:

Org A user cannot read/write/update/delete any Org B records.

Cross-org access is blocked across:

projects, estimates, takeoffs, tasks, timecards, invoices, bids, vendors, contacts, messages, files, notes, AI outputs, dashboards, settings, audit logs, webhooks

Every query path is scoped by orgId/tenantId at the data layer (not only UI).

Implement a “Tenant Guard Coverage Report”:

Enumerate all API routes

For each route, assert it is protected by:

authentication middleware

org scoping middleware/guard

role permission check (where applicable)

Fail the audit if any route:

is public unintentionally

lacks org scoping

accepts orgId from client without verification

uses raw queries without org filters

2.2 Role model verification (multi-user)

Create fixtures for:

Super Admin (platform-level)

Org Owner

Org Admin

PM / Estimator

Foreman / Field User

Accounting / CFO view

Vendor/Sub (if supported)

Read-only

For each role, verify:

Allowed pages load successfully

Disallowed pages are blocked (server denies + UI hides)

API returns 403 for forbidden actions (not 200 with filtered data)

Any “export” endpoints obey tenant scoping and role permissions

2.3 Super Admin controls audit

Verify super admin can:

view org list

impersonate (if supported) securely (logged + time-limited)

manage subscription tiers + feature flags per org

control branding / white-label settings per org

view global audit logs

disable orgs/users

view platform health dashboards
But super admin actions must:

write an immutable audit event

require re-auth / elevated confirmation (if implemented)

be blocked for non-super-admin always

3) Database & Data Integrity Audit
3.1 Schema checks

Automate checks that:

every multi-tenant table includes orgId/tenantId (or equivalent)

foreign keys are consistent

cascade behavior is safe

uniqueness constraints do not leak cross-org (unique indexes must include orgId where appropriate)

3.2 Migration sanity

Verify:

migrations run clean on empty DB

migrations run clean on existing DB

rollback strategy documented (even if not automated)

seed script does not violate constraints

3.3 Relation + orphan checks

Write a DB audit that detects:

orphaned rows

inconsistent statuses

missing required relations

cross-tenant foreign key references (should be zero)

4) API Audit: Routes, Contracts, Security
4.1 Route discovery

Generate a route manifest:

method, path, auth required, tenant guard applied, roles allowed
Write it to /audit-reports/routes.json.

4.2 Auth/session security

Verify:

session cookies: secure flags appropriate for env

CSRF protection if applicable

rate limiting for auth + sensitive actions

input validation (zod/yup) on payloads

consistent error handling (no stack traces leaking in prod)

4.3 File upload + downloads

Verify:

org scoping on file metadata and storage paths

signed URLs are time-limited

no path traversal

MIME/type validation

/admin/audit (super-admin only)
