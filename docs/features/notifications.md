# notifications — Delivery Framework, Email, Web Push, SMS, Slack/Teams Integration, Approval Workflow Notifications

## Overview

The notifications module delivers transactional alerts across multiple channels: in-app notification inbox, email (SendGrid), web push (VAPID), SMS (optional), and Slack/Teams channel webhooks. Notifications are generated by the event bus from every major module (bid status changes, time entry approvals, daily report submissions, pay application submissions, safety incidents, etc.). The approval workflow module routes multi-step approval requests through the same infrastructure.

## Data Models

**Key tables (`shared/schema/operations.ts`, `shared/schema/core.ts`)**

| Table | Description |
|---|---|
| `notifications` | In-app notifications: `userId`, `type` (enum 20+ values), `title`, `message`, `isRead`, `relatedEntityId`, `relatedEntityType`, `organizationId`, `createdAt` |
| `notification_preferences` | Per-user delivery channel preferences: `userId`, `channel` (EMAIL/PUSH/SMS/SLACK), `eventType`, `isEnabled` |
| `push_subscriptions` | Web push VAPID subscriptions: `userId`, `endpoint`, `keys` (JSON p256dh + auth) |
| `notification_delivery_log` | Delivery audit trail: `notificationId`, `channel`, `status` (SENT/FAILED/BOUNCED), `deliveredAt`, `errorMessage` |
| `approval_requests` | Multi-step approval records: `entityType`, `entityId`, `workflowId`, `currentStep`, `status` (PENDING/APPROVED/REJECTED/CANCELLED) |
| `approval_steps` | Individual steps: `approvalRequestId`, `stepNumber`, `approverId`, `status`, `decidedAt`, `comments` |
| `approval_workflows` | Configurable workflow templates: `name`, `entityType`, `steps` (JSON), `organizationId` |
| `slack_channel_connections` | Org Slack workspace connections: `workspaceId`, `channelId`, `webhookUrl`, `eventTypes` (JSON), `organizationId` |
| `teams_channel_connections` | Microsoft Teams webhook connections |
| `payroll_notifications` | Payroll-specific notification records from `payrollRoutes.ts` |

## Backend Routes

**File: `server/notificationRoutes.ts`**
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | `/api/notifications` | Lists user's notifications (paginated, filter: unread) | `requireAuth` |
| POST | `/api/notifications/:id/read` | Marks notification as read | `requireAuth` |
| POST | `/api/notifications/read-all` | Marks all as read | `requireAuth` |
| DELETE | `/api/notifications/:id` | Dismisses notification | `requireAuth` |
| GET | `/api/notifications/preferences` | Returns delivery preferences | `requireAuth` |
| PUT | `/api/notifications/preferences` | Updates delivery preferences | `requireAuth` |
| POST | `/api/notifications/subscribe-push` | Saves web push subscription | `requireAuth` |
| DELETE | `/api/notifications/subscribe-push` | Removes push subscription | `requireAuth` |

**File: `server/approvalRoutes.ts`** — multi-step approvals:
| Method | Path | Description | Auth |
|---|---|---|---|
| GET | `/api/approvals` | Lists pending approval requests for current user | `requireAuth` |
| POST | `/api/approvals/:id/approve` | Approves a step | `requireAuth` |
| POST | `/api/approvals/:id/reject` | Rejects with comment | `requireAuth` |
| GET | `/api/approvals/:id` | Approval request detail | `requireAuth` |
| GET | `/api/approval-workflows` | Lists org approval workflows | `requireRole('ADMIN','MANAGER')` |
| POST | `/api/approval-workflows` | Creates workflow template | `requireRole('ADMIN','MANAGER')` |

**File: `server/services/notificationService.ts`** — internal service:
- `insertNotification(record)` — single insert
- `insertNotifications(records[])` — bulk insert
- `sendPushNotification(userId, payload)` — VAPID web push via `web-push` npm
- `deliverToSlack(channelId, payload)` — HTTP POST to Slack webhook
- `deliverToTeams(webhookUrl, card)` — Teams adaptive card

**File: `server/services/notificationDelivery.ts`**
- `deliverNotification(notification, recipientPrefs)` — fan-out to all enabled channels

## Roles & Permissions

All authenticated users can receive and manage their own notifications.

| Action | Gate |
|---|---|
| View approvals | `requireAuth` (own approvals only) |
| Create approval workflows | `requireRole('ADMIN','MANAGER')` |
| Configure Slack/Teams channels | `requireRole('ADMIN')` + `canManageIntegrations` |

## Integration Points

- **Event bus** — `server/events.ts` exports `eventBus`; every module emits typed events (e.g., `bid.status_changed`, `pay_application.submitted`); `notificationDelivery.ts` subscribes and fan-outs
- **SendGrid** — `sendEmail()` in `server/email.ts` wraps SendGrid SDK; transactional template IDs configurable per notification type
- **Web push** — `web-push` npm library; VAPID keys in `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` env vars; service worker at `client/public/sw.js`
- **Rate limiting** — bulk fan-out is rate-capped at 50 sends/second to respect SendGrid limits
- **Payroll notifications** — `payroll_notifications` table drives special notification patterns for pay run events; separate `GET /api/payroll-notifications` route processes them
- **Email scheduling** — `project_log_email_schedules` table drives scheduled daily report email digests
