# Architecture Decisions

Full notes on every significant design decision made in SmartManageAI. Read the relevant section before touching the area it covers.

## Multi-Tenancy with AI-driven Customization

Platform supports multiple tenants with dynamic features and onboarding tailored by AI for specific trade types.

## Unified External Portal (`/portal`)

Provides a single entry point for Client, Subcontractor, and Vendor access with automatic role-based detection.

## Provider-Agnostic Integration Hub

A framework for centralized management of third-party service connections, gated by feature flags.

## AI Provider Routing

Provider-agnostic abstraction at `server/ai/providers/` covers chat completions and embeddings across the codebase. Three router entrypoints — `routedChatCompletion` (Takeoff family, gated by `AI_PROVIDER_TAKEOFF`), `routedGeneralChatCompletion` (every other chat call site, gated by `AI_PROVIDER_GENERAL`, default OFF = byte-identical to legacy OpenAI), and `routedEmbedding` (gated by `AI_PROVIDER_EMBEDDINGS`, OpenAI-only today; seam reserved for future Voyage/Cohere/Bedrock). All three meter `ai_tokens` + `ai_jobs` against `organization_subscriptions` and record per-call `provider`/`model`/`fallbackUsed` to `ai_action_audit`. CI guard `scripts/check-ai-router-bypass.mjs` (wired into `scripts/ci.sh`) fails the build if any new file under `server/` calls `openai.chat.completions.create` directly without either importing a router entrypoint OR carrying a `// ai-router-bypass: <reason>` annotation (top-of-file = whole file, or within 5 lines of a specific call = that call only). Full playbook + bypass policy: `docs/architecture/ai-provider-routing.md`.

## Domain-Specific Storage Seams

Gradually breaking up monolithic storage logic into domain-specific modules to improve maintainability and enforce access control (e.g., `server/bids/storage.ts`). See `docs/architecture/storage-pattern.md`.

## Scalable PDF Handling for Takeoffs

Implemented range-based GCS downloads and device-aware tile caching to efficiently manage large (up to 32 GB) PDF plans.

## Express Async Error Shim

`server/utils/expressAsyncShim.ts` patches `Layer.prototype.handle_request` at boot so async route handlers that throw without try/catch are forwarded to the central error middleware (Express 4 does not do this natively). `asyncHandler` is still exported for explicit, self-documenting wrapping.

## AI Estimator Sheet Indexing & Assemblies (Phase 1)

`server/services/aiEstimator/sheetIndex.ts` classifies each plan sheet by discipline (G/A/S/M/E/P/C/L/FP/T/Q/I/O) using AI + filename heuristics; persisted on `takeoff_sheets`. `draftTakeoffFromPlans` accepts `disciplines`/`tradeFilter` to scope plan docs per trade and supports up to 8 docs (was 4). Org-level factors, assemblies catalog, and legend symbols live in `ai_estimator_org_factors`, `ai_estimator_assemblies(_components)`, `ai_estimator_legend_symbols`.

## Materials Inventory & PM Engine

`shared/schema/features/inventory.ts` defines `inventory_locations` (WAREHOUSE/YARD/JOBSITE/TRUCK), `inventory_materials` (with optional barcode/QR), `inventory_stock_levels` (on-hand by material × location), `inventory_transactions` (RECEIPT / ISSUE / TRANSFER_OUT / TRANSFER_IN / ADJUSTMENT / CYCLE_COUNT with reason codes), and `inventory_cycle_counts` + `_lines`. All endpoints in `server/inventoryRoutes.ts`: receive (auto-bumps `purchaseOrderItems.quantityReceived`), issue-to-project (cost burden via avg unit cost), transfer (paired txns), adjust (ADMIN/MANAGER + reason), cycle counts (start/record/approve posts variance), reports (low-stock, slow-moving), and barcode lookup `GET /api/inventory/materials/by-barcode/:code`. Equipment PM engine `server/equipmentPmEngine.ts` walks active `equipment_maintenance_schedules` and inserts PENDING `equipment_repairs`; triggered via `POST /api/equipment/maintenance/generate-work-orders`.

**Idempotency (Task #2690)** is enforced at the DB layer by a real `equipment_repairs.schedule_id` FK to `equipment_maintenance_schedules` (`ON DELETE SET NULL`) plus a `pm_cycle_key` text column (`nextDueAt` ISO snapshot or YYYY-MM-DD stamp for hours-only schedules) and a partial unique index on `(schedule_id, pm_cycle_key) WHERE status NOT IN ('COMPLETED','CANCELLED')` (`migrations/0107_equipment_repairs_pm_idempotency.sql` + `server/utils/ensureEquipmentRepairsPmIdempotency.ts`). The engine catches SQLSTATE `23505` as `skippedReasons.raceLost` and returns `{checked, generated, skipped, skippedReasons:{alreadyOpen, raceLost, notDue}, scheduleIds}`. The `[PM:<scheduleId>]` description prefix is still written for human readability but is no longer load-bearing; the same migration backfills `schedule_id` + `pm_cycle_key` for historical PM-tagged rows. An hourly `pmDuplicateAuditTask` cron (`server/jobs/jobRunner.ts` → `auditPmWorkOrderDuplicates`) scans for duplicate active rows and orphaned `[PM:<id>]` rows that the backfill could not resolve; non-zero counts log at WARN. Frontend at `/inventory` (`client/src/pages/inventory.tsx`).

## Cross-Replica Messaging Bus

Unified messaging SSE/WS events fan out across pods via Postgres LISTEN/NOTIFY (`server/messagingBus.ts`); originating pod ignores its own echo via per-pod `PEER_POD_ID`.

## Project Closeout Package

`shared/schema/features/closeout.ts` defines configurable `closeoutTemplates` + `closeoutTemplateItems`, per-project `closeoutChecklists` (unique per project), `closeoutItems`, and `closeoutPackages`. `server/closeoutRoutes.ts` provides template CRUD, checklist init (with `DEFAULT_TEMPLATE_ITEMS` covering OM/Warranty/As-Built/Lien/Permit/Punch/Inspection), `/auto-pull` (scans warrantyDocuments, lienWaivers, projectPermits, punchListItems, projectInspections, planDocuments, assetHandoverItems and attaches sources by category), and `/export`. Punch list adds `GET /projects/:code/punch-list/walkthrough` grouping items by location for site walks. UI at `client/src/pages/project-closeout.tsx`, surfaced as a "Closeout" tab on Project Detail.

**Export is GCS-first and atomic (Task #2689)**: the route no longer dual-pipes the archiver to both the client and a captured buffer. Sequence is: (1) insert `BUILDING` row, (2) build the ZIP entirely into a buffer via `buildCloseoutZipBuffer()`, (3) verify integrity locally — `hasZipEndOfCentralDirectory(buf)` + sha256, (4) upload to a `.tmp/` key, (5) `tempFile.copy(finalFile)` to promote to `${PRIVATE_OBJECT_DIR}/${orgId}/closeout/${pkgId}-${filename}`, (6) best-effort delete the temp object, (7) stamp `READY` with `storageKey` + `fileSize` + `checksum` (sha256 hex) + `completedAt`, (8) return JSON `{ packageId, status, filename, fileSize, fileCount, checksum, completedAt, downloadUrl, downloadEndpoint }` with a 5-minute signed URL. Any failure between (2) and (5) leaves the row `FAILED` with `errorMessage`, NO final-key object, and an audit trail. `GET /api/projects/:code/closeout/packages/:pkgId/download` re-checks auth/org and the predicate `status = 'READY' AND storage_key IS NOT NULL AND file_size IS NOT NULL AND checksum IS NOT NULL AND completed_at IS NOT NULL` before 302-redirecting to a fresh signed URL — this is the authoritative delivery path so a client that disconnects after the POST response can still retrieve the verified package. Frontend `handleExport()` consumes JSON and uses an anchor click on `downloadUrl ?? downloadEndpoint`. Schema columns `checksum` + `completed_at` are added by migration `0106_closeout_packages_atomic_columns.sql` and mirrored at boot by `ensureCloseoutPackagesAtomicColumns`. Coverage: `server/__tests__/closeout-export-atomic.test.ts` (happy path / GCS failure / client-disconnect-after-success).

## Tenant Isolation via Postgres RLS

Defense-in-depth on top of `getOrgFilter`. Fail-closed `tenant_isolation` policy with `FORCE ROW LEVEL SECURITY` on every multi-tenant table (`migrations/0096_enable_tenant_rls.sql` + `server/utils/ensureRlsPolicies.ts`). `server/middleware/orgContext.ts` wraps EVERY authenticated request in a non-elevated `withOrgContext()` — SUPER_ADMIN sessions are NOT auto-elevated; cross-tenant access requires explicit `runAsSuperadmin(reason, fn, { actorId? })` which writes to the dedicated `superadmin_access_log` table BEFORE elevating and refuses on audit failure. The `db` export is a Proxy that routes through the ALS-bound client when a context is active. **`STRICT_TENANT_RLS=true` is the production default** — `server/index.ts` fails fast on boot in production when it's missing or `false`. With it on, the connect-default `app.is_superadmin` flips to `'false'` so any DB query that escaped a context wrapper returns zero rows instead of silently spanning tenants. All per-org loops in `server/jobs/jobRunner.ts` are wrapped via `withJobOrgContext("<job-name>", org.organizationId, …)` — including `processComplianceExpirations` (Task #2674 moved per-org dedupe + insert inside the wrapper so RLS pins them to the current tenant). Cross-tenant cron sweeps inherit a system-wide context for free because `withSchedulerLock` now wraps every locked tick in `withSystemJobContext("<job-name>")` (`server/utils/schedulerLock.ts`); `withSystemJobContext` is AUDITED — it delegates to `runAsSuperadmin("system-job:<name>", …)` so every cross-tenant elevation lands in `superadmin_access_log`. Lint guards: `scripts/check-db-imports.mjs` (proxy bypass) and `scripts/check-job-context.mjs` (background-job DB access without a context wrapper) — both wired into `scripts/ci.sh`. Full design: `docs/architecture/tenant-isolation.md`.

## Billing & Subscription Productization (Task #2482)

Plans/add-ons/quotas in `shared/billing/plans.ts` are the single source of truth (`PLAN_LIMITS` includes seats, AI tokens, AI jobs, AI vision docs, storage GB; price IDs resolved from env vars listed in `STRIPE_PRICE_ENV_VARS`). Stripe SDK lazy-init in `server/services/billing/stripeService.ts`; the suite is in `server/services/billing/{seatEnforcement,usageMetering,dunning,webhookHandler}.ts`. Self-serve endpoints `POST /api/billing/{checkout,portal,migrate-to-stripe,dunning/run}` plus `GET /api/billing/{seats,usage/all}`. Stripe webhook at `POST /api/stripe/webhook` (`server/stripeWebhookRoutes.ts`) — CSRF-exempt and signature-verified using `req.rawBody` from the JSON parser. Idempotency via the `stripe_webhook_events` table (unique `stripe_event_id`). Failed payments stamp `payment_failed_at`/`grace_period_ends_at`; `runDunningCycle` sends day 0/3/7 reminders and suspends on day `DUNNING_GRACE_PERIOD_DAYS`. Seat enforcement hooked into `POST /api/platform/users` via `assertSeatAvailable`; per-org overrides on `organization_subscriptions.{seat,ai_token,storage_gb}_quota_override`.

## Load Testing, Performance Budgets & Capacity Plan (Task #2488)

k6 suite under `loadtests/` exercises the top-20 endpoints (`loadtests/lib/endpoints.js`) at four profiles (`smoke`/`baseline`/`nightly`/`spike`, configured via `LOAD_PROFILE` in `loadtests/lib/config.js`). Per-endpoint p95 + error-rate budgets live in `loadtests/budgets.json` and are enforced by `loadtests/check-budgets.mjs` (regressionTolerance 15%). PRs run the smoke profile via the `load-test-smoke` job in `.github/workflows/ci.yml`; nightly + noisy-neighbor runs via `.github/workflows/load-test-nightly.yml`. The noisy-neighbor scenario (`loadtests/scenarios/noisy-neighbor.js`) splits VUs into heavy/quiet cohorts and asserts the quiet cohort stays within budget. Frontend Web Vitals captured by `client/src/lib/webVitals.ts` (no third-party dep — native PerformanceObserver) ship to `POST /api/observability/web-vitals` (CSRF-exempt, anonymous), feed an in-memory rolling aggregator (`server/webVitalsRoutes.ts`), and surface as `app_web_vitals_*` gauges on the `/metrics` Prometheus scrape. Capacity plan + tested ceilings + next bottleneck per tier: `docs/ops/capacity.md`.

## Prompt-Injection Guard Enforcement (Task #2683)

The `quarantineUntrustedText` / `quarantineDocumentBlocks` / `validateAiJsonOutput` contract from `server/ai/promptInjectionGuard.ts` is now mechanically enforced. New helpers `quarantineUserText(label, text)` (closes the stored-injection vector for tenant-DB strings spliced inline into prompts — sheet filenames, RFI bodies, assembly names) and `recordPromptInjectionDetection` / `recordDetectionMatches` (in-process counter) ship alongside an expanded pattern set (`delimiter_escape`, `encoded_payload_hint`, `im_start/end`, broader `tool_override` / `exfiltration` / `jailbreak`). Detection runs on a normalized form (zero-width chars stripped, whitespace collapsed) so `i\u200bgnore previous` no longer slips by. Counter is exposed on `/metrics` as `ai_prompt_injection_detections_total{route,pattern_id,action}` (action ∈ flagged | refused | quarantined). CI guard `scripts/check-prompt-injection-guard.mjs` (wired into `scripts/ci.sh`) fails the build if any new file under `server/` calls `openai.chat.completions.create` / `routedChatCompletion` / `callOpenAIForAnalysis` without either importing the guard or carrying a top-of-file `// prompt-injection-guard: <reason>` annotation. Reference site for stored injection: `server/services/aiEstimator/mapReduceDraft.ts` (sheet filenames now wrapped via `quarantineUserText` before being spliced into the discipline-batch envelope). Full playbook: `docs/architecture/prompt-injection.md`. Triage flow: `docs/runbooks/observability.md`.

## Support, Help Center & SLA

In-app `HelpWidget` + public `/help` and `/sla` pages back an internal-first ticket pipeline (`server/supportRoutes.ts`, `support_tickets` table). SLA tier targets (uptime %, channels, status cadence, priority-keyed first-response & resolution) live in **one canonical, framework-free module: `shared/sla/policy.ts`**. `server/support/slaPolicy.ts` re-exports `SLA_TIERS` from there (keeping only the business-hours/holiday computation helpers); `client/src/pages/sla.tsx` renders the public table via `buildTierTableRows()` from `shared/sla/format.ts`; and `docs/sla.md` is mechanically generated from the canonical module by `scripts/generate-sla-doc.ts`. CI guard `scripts/check-sla-doc.mjs` (wired into `scripts/ci.sh`) fails the build if the committed `docs/sla.md` drifts. A weekly KPI digest (`server/supportWeeklyReport.ts`, cron `0 13 * * 1`) emails recipients listed in `SUPPORT_REPORT_RECIPIENTS`. Help articles are Markdown files in `docs/help/` indexed by `manifest.json`. **Pattern note:** the same "canonical module + generated doc + CI parity check" recipe is the recommended fix for any other doc-vs-code duplication discovered later.

## Role-Based Sidebar Navigation Workflows (Task #2808)

The sidebar is no longer a flat role-filtered list. Each role is mapped to an ordered set of `WorkflowGroup[]` in `client/src/lib/rbac.ts` (`ADMIN_WORKFLOW`, `MANAGER_WORKFLOW`, `SUPERINTENDENT_WORKFLOW`, `ESTIMATOR_WORKFLOW`, `FIELD_WORKER_WORKFLOW`, `HUSTLER_WORKFLOW`). Each group has a `key: SidebarSection`, a display `label`, and an ordered `itemHrefs` allowlist. `AppSidebar.tsx` renders one collapsible section per group with a dedicated icon (`GROUP_ICONS: Record<SidebarSection, LucideIcon>`). The sidebar is **additive-safe**: any href in `itemHrefs` that fails the item's `visible()` check or a disabled feature-flag is silently omitted. New nav items must be added to (a) `NavItems` in `rbac.ts` and (b) the appropriate workflow group arrays — not just to the legacy `NavigationConfig` menus (those are kept for backward-compat consumers but are no longer the sidebar's source of truth).

## URL Tab Deep-linking (Tasks #2810, #2809)

Tabbed pages now read `?tab=<value>` from the URL on mount and sync the active tab back to the URL when the user switches tabs. Validated against a typed allowlist (`SAFETY_TABS`, `PAYROLL_TABS`) so invalid values fall back to the default tab without blank states. Implemented in `SafetyHubPage.tsx` (tabs: `dashboard / observations / osha / modules / training`) and `payroll-management.tsx` (tabs include `certified-payroll`). Follow the same pattern — `useSearch` from wouter, a `const TABS = [...] as const` tuple, `useState` initializer that validates the URL param, and a `useEffect` that re-syncs when the param changes — when adding tab deep-linking to other pages.

## Safety Training / Sequences Nav Cleanup (Task #2809)

`/sequences` was removed from `NavItems` (it is fully embedded as the "Sequences" tab inside `/crm`; the App.tsx route still exists for deep-links). `/safety-training` is retained in `NavItems` but is **only** placed inside `FIELD_WORKER_WORKFLOW`'s `safety_section` group. ADMIN/MANAGER/SUPERINTENDENT reach safety training through the `/safety` Safety Hub (which renders `SafetyTrainingPage` as a tab). This prevents duplicate sidebar entries. `safety-training.tsx` shows a "← Back to Safety Hub" link when accessed standalone by a non-field-worker; `sequences.tsx` shows "← Back to CRM" when accessed standalone.
